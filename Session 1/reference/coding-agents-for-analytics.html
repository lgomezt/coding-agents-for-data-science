Session 1

Coding Agents for Analytics Work

This session uses Antigravity, a coding agent from Google, to investigate a dataset and answer questions about it while keeping the work reproducible. This page covers the workspace and the requirements your analysis must meet before you write the first prompt.

Complete the setup and data-download steps first. Your Session 1 folder is the project root, and the original Seattle Public Library files belong directly in data/.

Workspace

For this session:

  • Antigravity is the coding agent. Send prompts in a Local conversation attached to Session 1.
  • VS Code is where you open, inspect, and run the Jupyter notebook (.ipynb).
  • The notebook is the analysis artifact: the file you keep, rerun, and share.
  • The project contains a data/ folder with the original files to analyze.

Antigravity should use the project's .venv environment and write accepted analysis into analysis.ipynb. Keep Antigravity and the notebook visible side by side so you can review commands, edits, and outputs as the work proceeds.

Open the notebook in VS Code

Use the project and Python environment prepared in setup. Ask Antigravity:

Work in Session 1 using its .venv. Create a blank Python notebook named analysis.ipynb if it does not exist. Confirm its full path and the Python interpreter path. I will open the notebook in VS Code. Do not analyze the data yet.
  1. In VS Code, choose File > Open Folder and open the same Session 1 folder.
  2. Install Microsoft's Python and Jupyter extensions if needed. Open analysis.ipynb from the Explorer.
  3. Choose Select Kernel at the top right, then Python Environments, and select the interpreter inside Session 1/.venv. If it is missing, run Python: Select Interpreter from the Command Palette and enter the path Antigravity reported.
  4. Use the play button beside a code cell to run it, or Run All to execute the notebook. Save the file to retain your edits and outputs.

Keep VS Code beside Antigravity. Name analysis.ipynb in your prompts and ask the agent to execute the saved notebook with the project environment and save its outputs.

Save your manual edits before asking Antigravity to change the notebook. After it finishes, reopen the file in VS Code to read the saved version. If VS Code reports a conflict, compare the versions before saving.

Run a cell containing import sys; print(sys.executable). Confirm that the path points inside Session 1/.venv.

Interface reference: Jupyter notebooks in VS Code.

Antigravity conversation basics

Most of what you type is a normal prompt. Requests such as “profile the data in data/” or “add a short notebook section explaining this chart” go to the agent as work requests.

Type / to see the available commands. Use /plan when you want to discuss an approach before implementation. The model selector below the prompt box changes the model; project settings control the working folders and permissions.

To start fresh, create a new conversation in the same project. To stop an active request, use the conversation's stop control. Stopping a request leaves any files already changed on disk.

A prompt describes the analysis task. Interface controls and slash commands help you manage the conversation. Before starting a new conversation, save decisions and verified facts in the project files.

Exercise: Prepare the workspace

Arrange Antigravity and the notebook in VS Code side by side. Identify where you will type prompts, where the agent should record code and outputs, and where the project's data/ folder is located.

What a coding agent does

A coding agent is an AI assistant connected to a working project environment. Antigravity can read files, write Python, run that Python, edit files, and produce plots in the course of answering one request. It can change the project rather than only describing it.

This raises a requirement that does not apply to a chat assistant. When the output is code and analysis, that output must be possible to follow and verify because the answer depends on specific data, transformations, calculations, and assumptions. As we will see in the lessons, by default, Antigravity may run calculations in a temporary terminal, report a conclusion, and leave no corresponding code in the notebook. The result cannot then be checked or reproduced.

Requirements for the analysis

Each analysis in this session must be:

  • Understandable — the code and explanations can be read and followed.

  • Reviewable — analytical steps are separated clearly enough to check individually.

  • Traceable — every stated result corresponds to specific code and output.

The process

The work proceeds as an iterative cycle rather than a single prompt:

  • Run a prompt.

  • Review what Antigravity did.

  • Identify what was missing or incorrect.

  • Record a rule to correct it.

  • Run again, then continue into the analysis.

The remaining pages apply this cycle to the checkout dataset: an initial broad prompt, a set of project rules, a structured investigation of the data, and a trend analysis.

Key points

  • A coding agent works inside a project environment, not only in a chat window.

  • The notebook is the analysis artifact students should be able to rerun and review.

  • Agent-produced analysis must be understandable, reviewable, and traceable.
