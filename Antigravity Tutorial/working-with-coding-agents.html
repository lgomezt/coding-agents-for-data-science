Working with coding agents

Set up a project, guide an agent through a small analysis, and check what it produces.

This guide uses the Antigravity standalone application. The habits apply to other coding agents, although their menus and configuration files may differ. You will work with a small, fictional library dataset and produce a Python script, a cleaned table, and a chart.

1. Meet your coding agent

A coding agent can read project files, write code, run commands, and use the results to decide what to do next. You give it an objective and constraints. You also review its decisions and the files it changes.

Three terms you will see in the application
TermMeaning
ApplicationThe software you open, such as Antigravity. It manages conversations, projects, and access to tools.
ModelThe AI component that interprets your request and proposes text, code, or a next action. You can select among the models your account provides.
AgentThe system that uses a model and tools to work on a task. It can inspect the result of one action before choosing another.

Which Antigravity do we use?

ApplicationWhat you work with
Antigravity
Called Antigravity 2.0 in the docs		A standalone workspace organized around projects and agent conversations. Use this application for the tutorial.
Antigravity IDEA code editor with an integrated agent, terminal, and development tools. Its layout is closer to VS Code. The menu instructions here are for the standalone app.

Download the standalone application from the official Antigravity download page, open it, and sign in. Select the standalone product if the page also offers the IDE.

Working in a desktop application does not mean the model runs on your computer. Follow your course or organization's data policy. Use the synthetic data in this guide rather than personal records, passwords, or confidential files.

Before continuing, confirm that you are in the standalone application and can find its project list and conversation area.

2. Settings and usage

Check your account before starting a long task. Available models and usage limits depend on your plan, and a task can stop when its allowance is exhausted.

Inspect your model quota

  1. Open Settings from the sidebar.
  2. Select Models. The page is titled Models & Usage.
  3. Read the remaining weekly allowance for the model groups shown. Check any shorter usage window and reset information displayed for your account.
  4. Use the refresh control if you need updated usage information. If credits or overage options appear, review them before authorizing paid usage.
  5. Return to the conversation and check the model selector below the prompt box. Its View Usage option is another route to the usage information.

Choose an available model for this exercise and keep it selected while learning the workflow. You can change models later. Changing the selection during a run does not switch the model already handling that turn.

Keep a local task running

Open Settings, select Application, and find Prevent Sleep under General. Enable it for a long local task. The setting keeps the computer from sleeping while the application is running.

Keep the app running, the computer powered, and the network available. Do not assume this setting overrides closing your laptop lid. Closing a Mac laptop normally puts it to sleep. For this exercise, leave the laptop open; you can step away and return to check progress.

The separate Keep In Menu Bar setting concerns keeping the app running when its windows are closed. Closing a window, closing the laptop lid, and quitting the app are different actions.

Find your selected model and its remaining weekly allowance. Confirm where to find Prevent Sleep before leaving a task running.

5. Give it useful context

Context is the information the model has available while handling your request. It can include your prompt, applicable instructions, conversation history, and material read through tools. Context has a limit. Large files and long conversations take space, and earlier details may be summarized or dropped.

A project folder tells the application where the agent can work. A file mention tells it which material is relevant. Neither proves that the model has already read every row.

Use @ to reference a file

Type @ in the prompt box, search for library_visits.csv, and select the file from the menu. Then write your request. Antigravity supports file and folder references; other applications may call this attaching context.

Inspect @library_visits.csv from the attached data folder without changing it. What does one row represent? Report the columns, number of data rows, date range, duplicate records, and missing values. Show a small preview and explain which issues need a decision before analysis.

In that example, insert the actual CSV using the mention menu. The label may include its folder name. Check that the response names the correct file and reports 13 data rows, excluding the header.

Make the request specific

Describe the question, relevant inputs, constraints, and outputs. Tell the agent how you will check the result. For this exercise, the question is: How did total monthly visits change across the two branches?

The missing value matters. A sum of the available records could look like a complete monthly total even when one branch is missing. Ask the agent to show the affected month before you decide how to handle it.

Open the CSV yourself. Find the repeated row and the empty visit count, then compare them with the agent's report. If it inspected the wrong file or guessed the contents, correct that before proceeding.

6. Direct the workflow

Before code runs, agree on the analysis decisions and expected files. A tool is an operation the agent can request, such as reading a file or running Python. Slash commands select a workflow; the agent may use several tools within it.

In Antigravity, type / to see the available commands. Select the command from the menu and add your request. These shortcuts are specific to the application. In another tool, use the plain-language request beside each command.

Commands used in this guide
CommandUse it when...Plain-language request
/planYou want to review the approach before implementation.Investigate the task and propose a plan for me to review.
/grill-meYour requirements need clarification.Interview me about the decisions we need to make.
/goalYou have a clear outcome for a longer run.Keep working toward this outcome and verify the result.
/browserYou need web research or page inspection.Use the browser to check the source and report what it says.
/learnYou want to save a useful correction for future tasks.Suggest how to save this lesson, then let me review the proposed changes.
/skill-nameYou want an installed skill applied.Use the named skill for this task.

/learn saves lessons by updating instructions; it does not retrain the model. You will practice saving those instructions in Session 1. /goal requests persistence; permissions and usage limits still apply, and the agent may need your input.

Show the cleaned table preview and the chart, and link the files you created. Report errors or unresolved questions instead of claiming completion.

Once you are comfortable supervising a run, you can use /goal for the same bounded task. Use the conversation's stop or cancel control if the run goes off track. Stopping does not undo files already changed; inspect them before restarting, and check whether any background command is still running. If the agent is waiting for approval or asks a question, read it before continuing.

Distinguish a running task from a task awaiting your input. When the agent finishes, open the files it names. If the run fails, read the error and ask for a specific correction.

7. Understand tools

A model can propose an action; the application carries it out through a tool and returns a result. A typical analysis uses file-reading tools, an editor, and a terminal. Watch their activity so you can tell what happened.

Tool operationExample in this projectWhat you check
Read a fileInspect the CSV header and records.The correct path, columns, and row count.
Edit a fileCreate src/analyze_visits.py.The changed file and whether the edit matches the plan.
Run a commandExecute the script with the project's Python.The command, interpreter, output, and error status.
Use a browserRead documentation or inspect a report page.The destination, information retrieved, and any requested interaction.

Reading documentation is different from submitting a form. Running an analysis is different from installing software. When an approval request appears, check the actual action and its scope. Prefer a one-time approval when you do not need a permanent rule.

If an action needs broader access, ask why. Do not disable the sandbox to work around an unexplained error. Content in files and websites can contain misleading instructions; it does not give the agent permission to upload your data or run unrelated commands.

Inspect one execution

Show the exact command you used to run this analysis and its output. Explain which files it read and wrote. Did any check fail? Do not rerun or modify anything just to answer.

For a browser example, ask /browser to find the official pandas documentation for handling missing values. Check that the response links to the relevant documentation. The CSV exercise does not require browser access to your accounts.

Identify one file read and one command execution in the activity log. Compare the reported output paths with the files on disk.

8. Create and use skills

A skill packages instructions for a particular kind of task. It can include scripts, examples, and templates. For example, a chart-review skill could check axis labels and missing-data handling whenever you ask for a chart review.

A skill describes a procedure you can reuse across tasks. A tool performs an operation, such as reading a table or running Python. Project notes record what happened in this analysis. A chart skill can guide the tools through the same checks each time you make a new plot.

What is inside a skill?

The required file is SKILL.md. Its opening metadata includes a required description explaining what the skill does and when to use it. Write that description in third person with explicit task triggers. Antigravity allows the name to be omitted; include it for portability. The rest explains the procedure. Supporting files are optional.

chart-review/
  SKILL.md
  examples/       (optional)
  scripts/        (optional)
  resources/      (optional)

Keep each project skill in .agents/skills/<skill-name>/SKILL.md. In the exercise below, you will create .agents/skills/economist-charts/SKILL.md inside Antigravity Tutorial. Global skills belong under ~/.gemini/config/skills/ on macOS/Linux.

9. Connect with MCP

MCP means Model Context Protocol. It is a standard way for an application to connect to programs that provide tools and information. The program providing those capabilities is an MCP server; it may run on your computer or on another system.

Common examples include GitHub for repositories and issues, Notion for pages, and Figma for design files.

Add GitHub to Antigravity

A personal access token (PAT) is a secret key that lets Antigravity access GitHub on your behalf. You choose which repositories it can access and whether it can read or change them.

  1. Open Settings, then Customizations. Under Installed MCP Servers, click Add MCP.
  2. Search for GitHub, choose GitHub's official server, and click Install (called Add in some versions).
  3. When asked for a token, open GitHub's personal access token page. Give it a name such as Antigravity practice, set an expiration date, and select only your practice repository under Repository access.
  4. Under Repository permissions, set Contents to Read and write to allow file edits, or Read-only for reading. Enable Issues and Pull requests with Read and write only if you want to manage those too.
  5. Click Generate token. Copy it into the GitHub MCP's token field in Antigravity and finish the installation.

Treat the token like a password. Paste it only into the setup field, never into a chat, notebook, or repository.

What can you do now?

With the permissions you granted, Antigravity can read your repositories, explain code, create or update files, manage issues, and open pull requests. You still need write access to a repository to change it.

Try a read request first:

Use the GitHub MCP to read README.md from lgomezt/coding-agents-for-data-science. Summarize it and link the file. Do not make changes.

Open the returned link and compare the README with the agent's summary.

Leave a useful handoff

Keep each conversation focused on a task. When it becomes long or changes direction, save the information a new conversation will need. Compaction summarizes a conversation; it may lose detail. Saved files remain available, but the next agent still needs to read the relevant ones.

Write project_notes.md inside Antigravity Tutorial with the question, project root and input file path, agreed cleaning decisions, outputs created, verified checks, unresolved issues, and the exact command and working directory to rerun the analysis. Include only facts supported by this project. Keep it concise and do not add credentials.

Open a new conversation in the same project and send:

Read @project_notes.md from the attached Antigravity Tutorial folder. Summarize the current state and identify the next useful step. Do not change files yet.

Compare the summary with your saved notes. Correct missing or inaccurate details before starting more work.

Context capacity and usage quota are different. Context limits how much information can be available for the current work. Quota limits how much model usage your account allows. Starting a fresh conversation can reduce accumulated context; it does not reset the account's weekly quota.
