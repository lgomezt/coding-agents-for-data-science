Economist-inspired charts

A worked design reference for the skill-building exercise. Compare it with your own research after you have drafted your first version.

The companion SKILL.md tells an agent when and how to use this file. This document holds the design decisions it needs to create a chart or restyle one consistently.

What this reference covers

This is a course interpretation of The Economist's digital design system, not an official chart template. Verified source details are identified below. Plotting settings, font substitutions, and the worked example are course adaptations.

The website describes digital-product design. It does not prescribe every Matplotlib setting. Its linked chart guide is dated May 2017; the PDF returned a website page instead of a PDF during this review. We therefore do not claim to have read the complete chart manual or the entire website.

Preserve the analysis. Changing a chart's appearance must not change its observations, missing values, units, or calculations. If the underlying analysis needs a correction, handle that as a separate task.

Typography

Verified: Econ Sans Condensed is assigned to charts and interactive graphics and uses lining figures. Other Economist typefaces serve body text, navigation, and tables. A public style page does not establish permission to redistribute its font files.

Course adaptation: use DejaVu Sans for this Python exercise, which ships with Matplotlib. In another plotting system, choose an installed sans serif and record the substitution. Do not download proprietary fonts or use The Economist's logo.

Chart layout

Verified: the web grid combines fluid columns with fixed gaps and gutters. The following figure layout is a course adaptation.

  1. Use a white canvas. Reserve separate space for the title, subtitle, plot, and footer.
  2. Align the title, subtitle, and footer to a common left edge. Add a short red rule above the title, without a logo.
  3. Start with a 7.2 × 4.5 inch figure. Suggested subplot bounds are left 0.10, right 0.96, bottom 0.25, top 0.73. Adjust for label length and inspect the export.
  4. Use light horizontal grid lines behind the data. Remove unnecessary spines and tick marks. For a new chart, use a small set of readable ticks. In a restyle, preserve the original limits and scale.
  5. Put units and period in the subtitle. Keep a source line and any missing-data or transformation note below the axis labels.

Matplotlib starting points: figsize=(7.2, 4.5), line width 2.2, marker size 4, grid width 0.6, and ax.set_axisbelow(True). Keep these settings local to the figure or an rc_context so other plots are unaffected.

Choose and label the chart

These are course analysis safeguards and plotting choices, not claims about undocumented Economist rules.

  • Change over time: use an ordered line chart. Retain missing dates as empty positions and break the line there. Never connect across an unobserved period just to make the plot look continuous.
  • Discrete comparisons: use bars with a zero baseline. Keep chronological order for months. A missing bar is an empty position with a note, not a zero-height observation.
  • Several measures: prefer separate panels when units differ. Do not add a second axis or rescale data to manufacture a visual relationship.
  • Titles: describe the measure unless a finding has been verified. State units, date range, and source. Do not imply causation from a descriptive trend.
  • Existing plots: inspect the source data and code. Preserve chart type, axis limits, transformations, and category order while styling. Propose analytical corrections separately.

Checks and exports

  1. Compare plotted values, missingness, category order, units, and transformations with the source table and generating code.
  2. Open the actual exported chart. Check text size, clipping, contrast, labels, and missing-data treatment. Colour alone must not identify a series.
  3. For this exercise, save a PNG at 200 dpi and an SVG. Keep a white background. Use svg.fonttype = 'none' for editable SVG text and record the required font; text can reflow on another computer.
  4. Preserve originals. Use separate rendering code and names such as visits_economist.png and visits_bars_economist.png, with matching SVGs. Check before overwriting an existing export.
  5. Report the output paths, exact run command, actual font, checks performed, and any unresolved issue. If an export was not opened, say that its appearance is unverified.
