Build and Deploy a Static Dashboard: Prompt Notes

These notes collect the prompts and deployment steps for the static dashboard lesson. The lesson follows Multi-Agent Workflows.

See the GitLab Pages deployment example: dashboard-starter-with-examples-8c1afe.pages.oit.duke.edu

Create a Dashboard

Use Session 1/dashboard/, prepared in the previous lesson, as the working directory for the dashboard prompts. Keep the agent attached to the Session 1 project so it can read its rules and skills. Save the website as index.html inside that dashboard folder.

Create a static dashboard website using plain HTML, CSS, and JavaScript that loads data directly at runtime from dashboard_data/digital_material_type_shares_by_year.csv, do not embed it; use Plotly.js to render exactly one interactive chart and one clearly written interesting finding derived from the CSV data, make the page responsive and visually polished.

Preview the page

A page that loads CSVs with fetch() needs a local web server. After the agent creates the first chart, ask:

Use the Session 1 .venv Python to start a local HTTP server bound to 127.0.0.1, serving Session 1/dashboard/ on an available port. Open the dashboard preview for me in the browser and keep the server running. Verify that its CSV loads, the chart renders, and the finding comes from that CSV. Report browser errors.

Inspect the dashboard preview that Antigravity opens. This browser preview runs the website; use VS Code for your notebooks and Python files. Ask Antigravity to refresh the preview after each change below.

Create a Subagent

Create a repo-local subagent definition for CSV data visualization work, saved as .agents/agents/csv-data-visualization.md relative to the Session 1 project root (outside dashboard/), with YAML frontmatter containing name: csv-data-visualization, description: Build and verify a static visualization from a CSV, and model: flash. Keep the task instructions below the frontmatter. The subagent should accept a CSV path and output location, inspect the CSV schema first, build a static responsive HTML/CSS/JS visualization, load the CSV directly at runtime with fetch() and never embed data or derived full datasets, use a browser visualization library such as Plotly.js, Apache ECharts, AG Grid Community 32 for tables, or Leaflet for map-style views, render exactly one interactive chart or requested table, compute exactly one clear finding from the runtime-loaded CSV, keep edits scoped to the requested output files, and verify syntax plus confirm the CSV is referenced rather than embedded.

Deploy on GitLab Pages

Set Up SSH Key

Ensure you have an SSH key added to your GitLab account. The commands below use gitlab.com; use your own GitLab host if it differs. Duke users can use their institutional account at Duke OIT GitLab and substitute gitlab.oit.duke.edu. If you already have a key, continue to the check below. If not, do the following:

  1. Generate an SSH public/private key pair on your laptop as explained in the GitLab SSH documentation.

  2. Upload the public half of that key pair to your GitLab account as explained in the add an SSH key documentation.

To check if you have set up your SSH key successfully, use the following command in your terminal:

ssh -T git@gitlab.com

You should see the following message, with your GitLab username filled in for USERNAME:

Welcome to GitLab, @USERNAME!

Set Up the Repository

Run this section from Session 1/dashboard/. Check that it contains only the dashboard assets, derived CSVs, generation scripts, and provenance notes before committing.

  1. Move index.html, index.css, any JavaScript files used by the page, and dashboard_data/ into a public/ folder.

  2. Create a new empty repository.

  3. Fill in the form. Make sure the README.md option is not selected.

  4. Add a new origin. Replace YOUR-NAMESPACE/mydashboard.git with the SSH repository path shown by your GitLab project, and replace the host if you use an institutional GitLab instance. Run these commands in the new dashboard folder.

git init --initial-branch=main
git remote add origin2 git@gitlab.com:YOUR-NAMESPACE/mydashboard.git
git add public/ scripts/
git diff --cached --stat
git commit -m "Initial commit"
git push --set-upstream origin2 main

  1. Refresh the GitLab repository and confirm that you can see your code.

Set Up GitLab Pages

  1. Visit Settings → General → Visibility, project features, permissions.

  2. Make sure the GitLab Pages setting is on.

  3. Go to Deploy → Pages and start the Pages setup. Configure the generated .gitlab-ci.yml with the following settings. You can also create this file at the repository root in GitLab’s editor. The pipeline needs an available GitLab runner.

image: alpine:latest

create-pages:
  stage: deploy
  script:
    - echo "Deploying static assets..."
  pages: true
  artifacts:
    paths:
      - public
  rules:
    - if: '$CI_COMMIT_BRANCH == "main"'

  1. Commit the .gitlab-ci.yml file. If your GitLab Pages setup opens a merge request, review and merge it into main.

  2. Check the pipeline under Build → Pipelines.

  3. View the pipeline and see it run.

  4. When the pipeline succeeds, visit the deployment link under Deploy → Pages.

  5. Confirm that the dashboard is deployed.
